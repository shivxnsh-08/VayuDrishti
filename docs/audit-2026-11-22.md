## Historical data

- The data.gov.in resource holds only the latest snapshot (every record had `last_update` 22-11-2026 18:00:00),
  so the past cannot be retrieved from it. The 24-point requirement is met naturally after 24 hourly runs.
- A backfill from OpenAQ v3 was added (`forecast-service/backfill/`, migration V3, `evaluation/sql/*historical*`).
  It is **not run yet**: it needs your `OPENAQ_API_KEY`, and India/CPCB coverage and per-location licences must
  be checked on the first trial run (`--limit-stations 5`). History is stored in `historical_station_aqi`,
  separately from live data, because its AQI is computed from concentrations rather than taken from CPCB.
  Unconvertible units (ppm/ppb) are skipped and counted, never guessed. Tested with mocked responses only (35 tests).


## Remaining limitations

- Forecasts stay `INSUFFICIENT_DATA` until each station has 24 hourly observations (expected around 2026-11-23 if no hour is missed).
- No model is trained yet; the API serves the persistence baseline and says so.
- The OpenAQ backfill is untested against the live API.
- AQI breakpoints, alert thresholds and advice rules still need checking against a primary CPCB / public-health source.
- Login throttling is in-memory (per instance, reset on restart).
